UNO R4 WiFi bridge firmware: Arduino's 0.6.0 plus **UDP push mode**,
revision 2. This revision is a **security update**: it replaces the
bridge's TLS root certificates, which still trusted the root and the
cross-signing path of eMudhra's compromised intermediate CAs.

> [!IMPORTANT]
> **Upgrade from `v0.6.0-interrupt.1`** if any sketch on your board
> opens TLS connections (`WiFiSSLClient`) without setting its own CA
> certificate. Push mode itself is unchanged.
>
> This is **not an Arduino release.** It is a fork of Arduino's 0.6.0
> bridge, built from this tag. Arduino's own 0.6.0 firmware — and this
> repository's
> [`v0.6.0-stock`](https://github.com/TonyMarkham/unor4-wifi-interrupt-bridge/releases/tag/v0.6.0-stock)
> image built from it — carries the same old certificates.

## What changed: the TLS root certificates

When a sketch opens a TLS connection without its own CA certificate,
the bridge checks the server against root certificates built into its
firmware. Until now that was Mozilla's list as of 2024-12-31.

In October 2026 the private keys of eight eMudhra intermediate CAs
turned out to be recoverable. Six of them are TLS intermediates that
chain to **emSign ECC Root CA - G3**, and all eight also exist
cross-signed under Sectigo's **AAA Certificate Services**. Browsers
blocked them; Mozilla removed emSign ECC Root CA - G3 on 2026-10-20.
The bridge checks no revocation, so with the old list a board would
have accepted a certificate signed with those keys.

The new list is:

- **Mozilla's root list as of 2026-10-20** (curl's `cacert.pem`, its
  published SHA256 verified; 118 roots). Neither emSign ECC Root CA -
  G3 nor AAA Certificate Services is in it.
- **GlobalSign Root CA**, kept from the old list. This bridge (ESP-IDF
  4.4) only checks the issuer of the topmost certificate a server
  sends, and Google, Cloudflare and arduino.cc send "GTS Root R4"
  issued by this root. Mozilla retired it in 2025 for its age, not for
  a compromise; without it, the board could not reach those sites.
- **Arduino's two certificates** for its IoT cloud, unchanged.

121 certificates in all. Roots Mozilla dropped since 2024 are gone,
and roots it added since are in.

## How to tell this firmware from others

| Where | Stock 0.6.0 | `interrupt.1` | This release |
|---|---|---|---|
| `AT+UDPPUSH=…` | `ERROR` | `OK` | `OK` |
| `AT+FWVERSION?` | `0.6.0` | `0.6.101` | `0.6.102` |
| USB product name (`lsusb -v`) | `UNO WiFi R4 CMSIS-DAP` | `UNO WiFi R4 CMSIS-DAP (interrupt)` | `UNO WiFi R4 CMSIS-DAP (interrupt)` |
| USB `bcdDevice` | `0.06` | `0.06` | `0.06` |

The patch number is 100 + the fork revision. The HID version report
and `AT+FWVERSION_U32` carry the same `102`.

## Push mode (unchanged from revision 1)

One AT command, sent by the RA4M1 for a UDP socket it has opened with
`AT+UDPBEGIN`:

```
AT+UDPPUSH=<sock>,<0|1>
```

`1` turns push mode on for that socket, `0` turns it off. The reply is
`+UDPPUSH: ` and `OK`, or `ERROR` for a socket that does not exist.
While it is on, every datagram received on that socket is sent to the
RA4M1 unasked, as one frame:

```
+UDPRX: <sock>,<len>|<len bytes>\r\n
```

No `OK` follows a frame. Rules for the RA4M1 side:

- A `+UDPRX:` frame can arrive between any two replies, including
  between a command and its reply. Parse it as its own frame.
- Do not send `AT+UDPPARSE` or `AT+UDPREAD` for a socket in push mode.
- Push mode is off for every new socket, and `AT+UDPSTOP` and
  `AT+SOFTRESETWIFI` turn it off. It survives a reset of the RA4M1, so
  a sketch should send `AT+SOFTRESETWIFI` at startup (`WiFiS3` does).
- Keep the traffic under the AT link's speed (115200 baud, about
  11 kB/s including frame headers); if the bridge's 16 KB output queue
  fills up, it drops its oldest data.
- Empty (zero-byte) datagrams are not forwarded.

Also from revision 1: when `AT+UDPBEGIN` or `AT+UDPBEGINMULTI` failed,
Arduino's bridge kept a pointer to the freed socket; the slot is now
cleared.

## Example code

- [`examples/UDPPushSleep`](https://github.com/TonyMarkham/unor4-wifi-interrupt-bridge/tree/v0.6.0-interrupt.2/examples/UDPPushSleep):
  an RA4M1 sketch that uses push mode as intended — it sleeps
  (`__WFI()`) until the UART interrupt of an arriving `+UDPRX:` frame
  wakes it, parses the frame, and counts how often it woke with
  nothing to read.
- [`examples/TLSCheck`](https://github.com/TonyMarkham/unor4-wifi-interrupt-bridge/tree/v0.6.0-interrupt.2/examples/TLSCheck)
  (new): connects through the bridge to well-known sites on different
  roots and to `untrusted-root.badssl.com`, which must be refused, and
  prints one summary line.

## How it was built and tested

Built from this tag (`v0.6.0-interrupt.2`) with
[`docs/build-interrupt-procedure.md`](https://github.com/TonyMarkham/unor4-wifi-interrupt-bridge/blob/v0.6.0-interrupt.2/docs/build-interrupt-procedure.md),
same toolchain as before (ESP32 platform 2.0.9, GCC 8.4.0, arduino-cli
1.5.1, esptool 4.5.1, espflash 2.0.0, Ubuntu 26.04). Two separate
builds produced this file byte for byte.

Tested with
[`docs/flash-interrupt-procedure.md`](https://github.com/TonyMarkham/unor4-wifi-interrupt-bridge/blob/v0.6.0-interrupt.2/docs/flash-interrupt-procedure.md)
on a UNO R4 WiFi: the board starts with the new USB name, accepts
sketch uploads, joins WiFi and reports `0.6.102`; push mode passed as
in revision 1; and `examples/TLSCheck` found Google, Cloudflare,
www.arduino.cc, api2.arduino.cc, GitHub, Let's Encrypt and Sectigo
trusted and `untrusted-root.badssl.com` refused.

## How to flash it

Follow
[`docs/flash-interrupt-procedure.md`](https://github.com/TonyMarkham/unor4-wifi-interrupt-bridge/blob/v0.6.0-interrupt.2/docs/flash-interrupt-procedure.md),
steps 1–4; steps 5 and 6 test push mode and TLS. It assumes you have
already followed `docs/build-original-procedure.md` once on your
computer, for the tools and the serial-port access.

The only difference from the procedure: instead of building the image,
check the download. In the folder that holds both files:

```
sha256sum -c SHA256SUMS
```

It must print `UNOR4-WIFI-S3-0.6.0-interrupt.2.bin: OK`. If it prints
anything else, do not flash the file. Then, in step 4.1, use the path
of the file you downloaded.

> [!WARNING]
> Flash this file only at address `0x0`, with espflash 2.0.0, exactly as
> step 4.1 shows. Do not use the esptool command in Arduino's README:
> its offsets do not match this board's partition layout.

## Going back to stock

Flash the `v0.6.0-stock` image the same way; the flash procedure's
"Going back to stock" section has the exact steps. Note that stock
carries the old certificates described above.
